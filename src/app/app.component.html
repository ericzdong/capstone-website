Why this matters

Bring your existing component library into A2UI.

Many development teams already use Storybook to build, document, and test their UI components. But those components cannot automatically be understood or used by an A2UI agent.

Our project bridges that gap by extracting component metadata, mapping it to the A2UI catalog format, validating the generated definitions, and producing a catalog for an A2UI workflow.

How it works

A practical bridge between two component ecosystems.

One pipeline turns Storybook's component metadata into a catalog that follows the structure A2UI expects.

1

Input

Discover Storybook metadata

Read the stories and component information already produced by a Storybook build.

2

Transform

Map schemas and fill gaps

Translate useful fields into A2UI definitions and handle missing or unsupported metadata.

3

Verify

Validate the catalog

Check the generated data against typed models before it reaches an agent workflow.

4

Output

Load it into A2UI

Produce a catalog that can be tested in Composer and supplied to an A2UI-capable agent.
